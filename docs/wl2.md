# Wavelog API v2 Compatibility Layer (Draft)

The existing clients (hislog, speech-to-qso, grayline, wavelog-tools) keep
talking Wavelog API v2 to jl1his-logger until they move to the native API.
Their base URL becomes `PUBLIC_ORIGIN/wl2`, so their requests arrive at
`/wl2/index.php/api/v2/<resource>`. Only what these clients use is matched; see
"Wavelog API v2 Compatibility Layer" in [decisions.md](decisions.md).

## Requests and Errors

A request carries a `wl2` API token as `Authorization: Bearer <token>`. The
token is fixed to one Logbook, which every request reads. A missing or unknown
token, a native token, a session cookie, or a token whose user lost the
Logbook's Membership is `401`.

Errors are Wavelog's envelope, `{"error": {"code": "...", "message": "..."}}`:

| Status | `code` | When |
| --- | --- | --- |
| `400` | `validation_error` | An unsupported or malformed parameter |
| `401` | `invalid_token` | See above |
| `404` | `not_found` | An unknown path, or a `station_id` no Station has |
| `500` | `internal_error` | A server failure |

Successful answers are `{"data": ..., "meta": {...}}`.

## Stations

`GET station` lists the Logbook's Stations that have a Wavelog ID and are not
archived, ordered by that ID. A Station without a Wavelog ID cannot be reached
through `/wl2`.

| Key | Source |
| --- | --- |
| `id` | `wavelog_id` |
| `uuid` | The Station's ID |
| `name`, `callsign` | The Station's name and callsign |
| `gridsquare`, `city`, `country`, `state`, `cnty` | `MY_GRIDSQUARE`, `MY_CITY`, `MY_COUNTRY`, `MY_STATE`, `MY_CNTY` |
| `iota`, `sota`, `wwff`, `pota`, `sig`, `sig_info` | `MY_IOTA`, `MY_SOTA_REF`, `MY_WWFF_REF`, `MY_POTA_REF`, `MY_SIG`, `MY_SIG_INFO` |
| `dxcc`, `cq`, `itu`, `power` | `MY_DXCC`, `MY_CQ_ZONE`, `MY_ITU_ZONE`, `TX_PWR` as numbers |
| `active` | Always `false`; there is no active Station here |

A field the Station does not have is `null`.

## QSOs

`GET qso?format=adif` reads the Logbook's live QSOs in insertion order (`seq`),
as ADIF with codepoint lengths. `format` is required and only `adif` is
supported.

| Parameter | Meaning |
| --- | --- |
| `since_id` | Only QSOs whose `seq` is greater; default `0` |
| `page`, `per_page` | Pages of that order, from 1; `per_page` defaults to 100 and is capped at 5000 |
| `station_id` | Comma-separated Wavelog IDs of Stations, archived ones included |
| `callsign` | The call, ignoring case |
| `callsign_match` | `exact` (the default) or `plain`, which matches the base call, so `JA1ABC` finds `JA1ABC/P` and `KH6/JA1ABC` |
| `band`, `mode` | Ignoring case |
| `qsl_filter` | Comma-separated `qsl`, `lotw`, `eqsl`: QSOs confirmed by any of them (`QSL_RCVD`, `LOTW_QSL_RCVD` or `EQSL_QSL_RCVD` is `Y` or `V`). `qrz` and `clublog` are not recorded here and are refused |
| `qso_since`, `qso_until` | `YYYY-MM-DD`, both days included |

```json
{
  "data": { "exported": 2, "lastfetchedid": 1290, "adif": "Generated by jl1his-logger\n..." },
  "meta": { "page": 1, "per_page": 5000, "count": 2, "total": 2, "total_pages": 1, "has_more": false }
}
```

`lastfetchedid` is the `seq` of the last QSO on the page, or `since_id` when
the page is empty; a client continues with it as the next `since_id`. `total`
and `total_pages` count every QSO the parameters match, `since_id` included,
and `has_more` says whether a later page follows. Edits and deletions are not
reported: `since_id` only ever adds QSOs. The native API's changes and event
stream cover them.

## Catalog

`GET catalog?topic=contest` lists the distinct `CONTEST_ID`s of the Logbook's
live QSOs, ignoring case, as `{"contest": "<id>", "name": null}`. There is no
contest table, so there are no names. Other topics are `400`; `subdivisions`
waits for the reference data.
