# Database Schema

The SQLite schema behind the decisions in [decisions.md](decisions.md). The
source of truth is `server/migrations/`; this page describes the schema they
build up to and explains the choices the SQL cannot. Applied migrations are
never edited; every change is a new migration, which also carries existing rows
over. sqlx applies pending migrations when the server starts and records each
one with its checksum in `_sqlx_migrations`; see "Migrations and Deployment" in
decisions.md.

## Conventions

- **IDs** are UUIDs stored as lowercase hyphenated `TEXT`. QSO IDs are UUID v7
  generated by the client; every other ID is generated by the server.
- **Timestamps** that record when something happened in the application
  (`created_at`, `updated_at`, `deleted_at`, `expires_at` and so on) are RFC
  3339 in UTC with second precision, such as `2026-10-22T04:05:06Z`. They sort
  as strings. QSO dates and times are separate: see the `qsos` table.
- **Secrets** are never stored in plaintext. `token_hash` columns hold the
  SHA-256 of the token as a `BLOB`; the plaintext is shown once when issued.
- **JSON string maps** (`fields`) are `TEXT` holding a JSON object whose keys
  are ADIF field names and whose values are strings. A `CHECK` enforces that
  the value is valid JSON and an object.
- **Enumerations** with a fixed, application-defined set of values (`role`,
  `kind`) carry a `CHECK`. ADIF values do not: they are stored as they
  arrived.
- **Connections** set `PRAGMA journal_mode = WAL`, `PRAGMA foreign_keys = ON`
  and `PRAGMA busy_timeout` on open. Foreign keys are only enforced when the
  pragma is on, so it is part of the connection options, not the migration.
  Migration 12 runs outside a transaction so that it can turn the pragma off
  while it rebuilds `stations`, which `qsos` and `station_favorites`
  reference, and turns it back on at its end.
- **Logbook ownership** is enforced with composite foreign keys: a QSO and
  its Station and Instrument belong to the same Logbook, as do an export
  batch and all its QSOs. The referenced tables have `UNIQUE (logbook_id, id)` constraints.
- Rows are not deleted where the design says archive or disable: `stations`
  and `instruments` are archived (`archived_at`), `users` are disabled (`disabled_at`) and
  `qsos` get a tombstone (`deleted_at`). Deleting a Logbook is the one
  destructive operation; it cascades to everything the Logbook owns.

## Tables

### `users`, `passkeys`, `registration_tokens`, `sessions`

- `users.callsign` is the personal callsign, uppercase, and identifies the
  person. `role` is the instance role (`admin` / `user`). A disabled user
  keeps their rows and `created_by` / `updated_by` references but cannot sign
  in.
- `passkeys` is one row per registered credential. `passkey` is the
  webauthn-rs `Passkey` serialized as JSON;
  `credential_id` is kept separately so that an assertion can find its row.
- `registration_tokens` back the one-time registration URLs: the first admin
  from `setup`, invitations of new users and passkey re-registration. The
  user row exists before the link is issued, so the token always points at a
  user. `created_by` is the admin who issued it, or `NULL` for `setup`.
  A token is valid for 24 hours unless the CLI gives another period, and
  issuing one deletes the user's unused ones. `setup` can issue one only for
  an admin without passkeys.
- `sessions` is the `__Host-` cookie session, looked up by the hash of the
  cookie value; `id` names it to the user and never reveals the cookie. It
  lasts 30 days; at most once a day a use sets `last_used_at` and pushes
  `expires_at` to 30 days from now, never past 90 days after `created_at`. `user_agent` is the browser it was
  created from, truncated. Expired rows are deleted when a session is
  created.
- Disabling a user deletes their `sessions`, `api_tokens` and unused
  `registration_tokens`; `passkeys` stay.

### `logbooks`

A personal or club station. Besides its name it holds the per-Logbook
counters:

- `last_seq` and `last_updated_seq` are the last values handed out. A write
  transaction increments them with `UPDATE ... RETURNING` before inserting or
  updating the QSO, which also serializes writers of the same Logbook. They
  only grow, so a value is never reused even after a deletion.
- `cursor_generation` is an opaque string that every differential response
  and SSE stream reports next to `updated_seq`. A backup restore replaces it,
  and a client whose stored generation differs discards its cursor and
  resyncs. It is stored once per Logbook rather than on every row; the API
  still presents it with each row, which is what decisions.md describes.
- `area_field` and `area_label` are the Logbook's area code field: the ADIF
  field name, upper-cased, and the label the screens show for it. Both are
  `NULL` when the Logbook has none.

### `memberships`

The Logbook role (`owner` / `operator`) of a user in a Logbook. One row per
pair. There is no instance-level read access: even an admin needs a row here
to read QSOs, and `rescue_operations` records the exceptions.

### `stations`

A Station Location of a Logbook.

- `callsign` becomes `STATION_CALLSIGN` of every QSO entered with the
  Station.
- `fields` is the JSON map of the other defaults that are baked into a new
  QSO, keyed by their ADIF name (`MY_GRIDSQUARE`, `MY_CITY`, `MY_STATE`,
  `MY_CNTY`, `MY_POTA_REF`, `MY_SIG`, `MY_SIG_INFO`, `MY_DXCC`, ...). The
  web UI edits them as form fields; the server does not need columns for
  them because nothing searches Stations by them. `MY_RIG`, `MY_ANTENNA`
  and `TX_PWR` are never among them; they belong to `instruments`.
- `archived_at` hides the Station from entry. QSOs keep pointing at archived
  Stations.
- Migration 12 rebuilt the table without the `wavelog_id` of the former
  `/wl2` compatibility layer.

### `instruments`

The equipment of a Logbook: a rig, an antenna and a default TX power,
independent of the Station.

- `my_rig`, `my_antenna` and `tx_pwr` become `MY_RIG`, `MY_ANTENNA` and
  `TX_PWR` of a QSO entered with the Instrument, where the QSO has none;
  `NULL` leaves the field unfilled. `tx_pwr` is a decimal number of watts
  above zero.
- `fields` is the JSON map of other defaults, keyed by their ADIF name like
  a Station's. They are baked in before the Station's, so they win over it.
- `archived_at` hides the Instrument from entry. QSOs keep pointing at
  archived Instruments.

### `station_favorites`, `instrument_favorites`

The Stations and Instruments a member has marked as favorites: one row per
user and Station or Instrument, with the Logbook. Composite foreign keys tie
each row to the user's Membership and to a Station or Instrument of the same
Logbook, both `ON DELETE CASCADE`, so removing a Membership removes its
favorites. Marking a favorite does not touch the Station or Instrument row.

### `frequency_favorites`

The favorite frequencies of a user: `id`, `user_id` (`ON DELETE CASCADE`),
`freq` (MHz as the server formats it), `freq_hz` (above zero), `mode`,
`submode` (empty when there is none) and `created_at`. They belong to no
Logbook. `UNIQUE (user_id, freq_hz, mode, submode)` keeps each frequency and
mode once per user and serves the list, which is ordered by `freq_hz`.

### `qsos`

One row per QSO, including deleted ones.

**Bookkeeping**

| Column | Meaning |
| --- | --- |
| `id` | Client-generated UUID v7. `POST` with an existing ID returns this row. |
| `logbook_id`, `station_id` | The Logbook and the Station Location. `station_id` is for classification and search only; the ADIF values are in the row. |
| `instrument_id` | The Instrument, or `NULL` for none. Like `station_id`, it classifies the row; the ADIF values are in the row. |
| `seq` | Insertion order within the Logbook. |
| `updated_seq` | Update order within the Logbook; also set on insert and on delete. The SSE event `id` and the differential cursor. |
| `revision` | Starts at 1 and increments on every update. An update must send the revision it is based on. |
| `created_by`, `updated_by`, `created_at`, `updated_at` | Who and when. API-token writes record the token's user. |
| `deleted_at` | The tombstone. A deleted row keeps its ADIF columns, gets a new `updated_seq` and is never removed. |

**ADIF columns.** The column name is the ADIF field name in lowercase. The
value is the ADIF string as received, with no normalization, and `NULL` when
the field is absent. The field is removed from `fields` when it has a column.

| Group | Columns | Notes |
| --- | --- | --- |
| Required | `call`, `qso_date`, `time_on`, `band`, `mode`, `station_callsign` | The minimum for a record. `station_callsign` is baked from the Station. |
| Contact | `time_off`, `submode`, `freq`, `rst_sent`, `rst_rcvd`, `operator`, `name`, `qth`, `gridsquare`, `state`, `cnty`, `dxcc`, `tx_pwr`, `comment` | `freq` may be `NULL`; the server never fills it in. `cnty` holds county and JCC / JCG codes as strings, leading zeros included. `dxcc` is the entity number as a string and is not rewritten by reference data updates. |
| Contest | `contest_id`, `stx_string`, `srx_string` | `STX` / `SRX` numeric serials stay in `fields`. |
| QSL | `qsl_sent`, `qsl_sent_via`, `qslsdate`, `qsl_rcvd`, `qsl_rcvd_via`, `qslrdate`, `eqsl_qsl_sent`, `eqsl_qslsdate`, `eqsl_qsl_rcvd`, `eqsl_qslrdate`, `lotw_qsl_sent`, `lotw_qslsdate`, `lotw_qsl_rcvd`, `lotw_qslrdate` | The QSL state of record. `qsl_required` is `qsl_sent IN ('R', 'Q')`, received is `qsl_rcvd IN ('Y', 'V')`; neither is stored. |
| Own station | `my_gridsquare`, `my_city`, `my_state`, `my_cnty`, `my_pota_ref`, `my_sig`, `my_sig_info` | Baked from the Station at creation. `my_pota_ref` holds several parks comma-separated as ADIF does; the POTA export splits it. |
| Everything else | `fields` | Unknown standard fields and `APP_*`, kept as they arrived. |

**Derived columns.** Computed by the server on every write from the ADIF
columns, never written by clients, never exported.

| Column | Definition |
| --- | --- |
| `call_base` | `call` uppercased with portable prefixes and suffixes removed (`JL1HIS/1`, `JL1HIS/P` and `JA1XYZ/QRP` give `JL1HIS` and `JA1XYZ`). The home callsign is the longest slash-separated segment, the first one on a tie (`KH6/W1AW` gives `W1AW`, `VP2E/W1AW` gives `VP2E`). Previous-contact lookup, plain callsign search, the callsign sort order and duplicate candidates use it. |
| `qso_time` | `qso_date` + `time_on` as Unix seconds in UTC. `time_on` with four digits counts as `:00`. Sorting, time range filters and duplicate detection use it. |
| `freq_hz` | `freq` (MHz, decimal string) as integer Hz, or `NULL`. |

**Indexes.** All partial on `deleted_at IS NULL` except the unique
constraints, which cover tombstones for sequence uniqueness and foreign
key references.

| Index | Serves |
| --- | --- |
| `UNIQUE (logbook_id, updated_seq)` | Differential fetch: `updated_seq > ?` ordered, tombstones included. The SSE catch-up query is the same. |
| `UNIQUE (logbook_id, seq)` | Keeps the insertion order unique within the Logbook. |
| `UNIQUE (logbook_id, id)` | Composite foreign key from `export_batch_qsos`, enforcing Logbook ownership. |
| `(logbook_id, qso_time)` | The log list and date filters. |
| `(logbook_id, call, qso_time)` | Searching an exact `call`. |
| `(logbook_id, call_base, qso_time)` | Previous contacts with a station for `lookup`, and duplicate candidates: rows with the same `call_base` whose `qso_time` is within 15 minutes, kept when `call`, `band` and `mode` match ignoring case and surrounding spaces. `call` is stored as it arrived, so its index cannot answer that. |
| `(logbook_id, station_id, qso_time)` | Per-Station listing and export. |
| `(logbook_id, instrument_id, qso_time)` | Per-Instrument listing and rewrites. |
| `(logbook_id, qsl_sent)` | The QSL work queue. |

**Write flow.** In one short transaction opened with `BEGIN IMMEDIATE`, so
no other writer runs between the reads and the writes (`server/src/store/qso.rs`):

1. A create looks the ID up first. A row of the same Logbook is returned as it
   is, tombstone included, so a resend is idempotent and hands out no numbers;
   a row of another Logbook is a conflict.
2. The Station and the Instrument, if any, are read from the same Logbook.
   The Instrument's values are baked in where the QSO has none, then the
   Station's, `OPERATOR` defaults to the user's callsign, and the record
   is checked. Extra-field keys must be valid uppercase ADIF names and must
   not name a core column, even if that column is empty. Creates and updates
   reject invalid field placement before numbering or saving, so a caller
   can handle the validation error and commit other work safely. Possible
   duplicates become warnings.
3. `UPDATE logbooks SET last_seq = last_seq + 1, last_updated_seq = last_updated_seq + 1 WHERE id = ? RETURNING last_seq, last_updated_seq`
   for a create; an update or delete increments `last_updated_seq` only.
4. `INSERT` for a create. An update first compares the revision it was based
   on, then runs `UPDATE qsos SET ..., revision = revision + 1, updated_seq = ? WHERE id = ? AND revision = ?`.
   A delete sets the tombstone the same way; deleting a deleted row returns it
   unchanged.

### `api_tokens`, `api_token_scopes`

A token belongs to a user and is limited to the Logbooks listed in
`api_token_scopes`. Every scope needs a Membership of the user when the token
is issued, and access revalidates the Membership on every use. `last_used_at`
is written at most once a day. Revoking a token deletes the row. Migration 12
deleted the `wl2` tokens of the former `/wl2` compatibility layer and dropped
the `kind` column, since every token opens the native API.

### `export_batches`, `export_batch_qsos`

An export records which rows it covered and at which `revision`. `kind`
names the external processing (`adif`, `pota`, `eqsl`, `lotw`, `qsl_card`).
Applying the result (for example marking `QSL_SENT = Y` after the cards went
out) touches only the rows in the batch, and a row whose `revision` moved
since the export, or that was deleted, is skipped and reported rather than
silently overwritten. `applied_at` is set when the result has been applied,
and a batch is applied only once. `adif` and `pota` batches record what was
exported and have nothing to apply. decisions.md lists the fields each kind
sets.

`export_batch_qsos.logbook_id` participates in composite foreign keys to
both `export_batches` and `qsos`, so a batch cannot include a QSO from
another Logbook. Deleting a batch or a QSO cascades to its batch entries.

### `rescue_operations`

An admin acting on a Logbook they are not a member of (reading or exporting
its QSOs, reassigning its owner). One row per operation with the actor, what
was done and the reason given, written in the same transaction as the
operation.

### `reference_versions`

The active version of each reference data set (only `cty`, enforced by a
`CHECK`), written when an admin installs a file with the
CLI or uploads a CTY archive, with the file's SHA-256 as `checksum`. Migration 9
removed the `dxcc` kind and forgot the `cty` row of a plain `cty.dat`, which
must be installed again as an archive; migration 10 removed the
`subdivisions` kind, now built into the server, and migration 11 the `parks`
kind. The data itself
lives in the files `config.toml` points at; the server reloads a file when its
row changes, and the web UI reads this table to show the versions.

## Not in the schema

- **ADIF tables** (bands, modes, QSL values, DXCC entities, subdivisions):
  compiled into the server from `assets/adif/`, from which the
  client generates its own.
- **Import staging**: an import previews and applies within one request; the
  web UI sends the file again to apply what it previewed.
- **Instance settings**: migration 14 dropped the `settings` key / value
  table, which only the former CLI wrote and nothing read.
- **Change history**: none, by decision. Triggers that stack the previous
  JSON of a row can be added later without changing this shape.
